# QDII 基金监控 · 数据扫描逻辑说明

> 面向产品视角的完整链路说明，最后更新：2026-09-19

## 一句话总览

每天定时去各数据源"抄表"，把每只基金的申购状态、买入限额、业绩数据抄回来存档，和上一次对比，有变化就记录并通知，最后生成页面展示用的数据文件。

---

## 一、监控范围（监控谁）

| 板块 | 覆盖基金 | 纳入方式 |
|---|---|---|
| 美国主表（/qdii） | 跟踪纳斯达克100、标普500 的场外基金，约 85 只 | 按基金名称关键词自动纳入，市场新发基金自动进清单 |
| 世界视野（/qdii/world） | 其他市场的指数基金与主动基金，81 只 | 维护一份显式监控清单（world_watchlist.json），与页面静态档案同集，新份额需两处同步添加 |
| 主动权益母池 | 104 只主动 QDII | 冻结清单；数据正常入库，导出的母池文件页面前端暂未消费 |

**排除规则**：场内交易的 ETF（只能场内买卖，无申购概念）、美元/现汇份额（人民币用户买不了）不监控。

---

## 二、数据从哪来（四路数据源）

| 数据内容 | 来源 | 采集方式 |
|---|---|---|
| 申购状态、赎回状态、**代销**日累计限额、购买起点、手续费 | 天天基金·申购状态接口 | 一次拉全市场，按规则筛选 |
| 近 1/6/1/3 年+成立以来收益率、成立日、基金规模、跟踪标的 | 天天基金·每只基金的主页 | 逐只抓取 |
| 年化跟踪误差 | 天天基金·特殊指标页 | 逐只抓取 |
| 管理费/托管费/销售服务费率 | 天天基金·费率页 | 逐只抓取 |
| **直销**日累计限额 | 安鑫乐「跨境额度日报」 | 网站为主源；AI 公众号结果通过统一导入脚本入库（AI 执行任务尚待确认配置） |

**分工原则**：代销限额和基金基本信息全部来自天天基金；直销限额只来自安鑫乐（量化实验室）；两路数据按基金代码对号入座、互不覆盖。

---

## 三、每天的扫描流程（按执行顺序）

1. **拉取全市场申购状态**。失败自动重试 3 次（间隔 1 分钟）；彻底失败则本轮放弃，所有数据保持上一次的状态不动，绝不写坏。
2. **筛选**出监控名单内的基金，剔除场内 ETF 与美元份额。
3. **补充详情**：逐只抓取收益率、成立日、规模、跟踪误差、各项费率。
4. **合并直销限额**：读取安鑫乐网站并写入直销额度表，与已入库的 AI 结果按代码、逐基金数据日期合并；旧数据不覆盖新数据，同日网站有效值优先。网站缺失值不清除历史有效值。
5. **存档**：每只基金每天写入一条快照，形成历史序列（供页面展示历史变化节点）。
6. **对比变更**：与最近一次快照比较，三项指标有变就记一笔——申购状态、赎回状态、代销限额。
7. **导出页面数据**：
   - 美国页数据文件：最新状态 + 每只基金全量历史 + 最近 200 条变更
   - 世界页数据文件：状态、限额、直销、详情字段、历史
   - 主动权益母池文件（内部用）
8. **邮件通知**：当天变更发送给订阅者；订阅者可按地区订阅，只收自己订阅地区的变动。

**执行时间**：扫描脚本由服务器 cron 在每天 9:00、12:00、15:00、18:00、20:00 执行，代码不自行注册扫描任务；通知默认每天 20:30 检测一次。发布时需分别核对服务器 crontab 与 `NOTIFY_CRON`（同日相同变化不重复记录）。

## 四、页面展示规则（均已拍板确认）

- **状态徽章**：开放申购 / 限大额申购 / 暂停申购
- **限额数字**：超过 5 位数（≥10 万）显示"X 万"，上亿显示"X 亿"，其余千分位
- **代销列**：天天基金口径如实展示；暂停申购显示"—"
- **直销列优先级**（从上往下）：
  1. 暂停申购 → 整行"—"（代销、直销都是，即使档案里有直销档位记录）
  2. 有网站或 AI 入库的有效直销档位 → 用档位数值；明确为 0 显示“—”，不能当缺失回退
  3. 无有效直销记录（null）→ 默认与代销同额（业务规则：不存在有代销无直销的基金公司）
  4. 代销无限额 → 直销"无限额"
- **"无限额"判定**：天天基金用一个超大哨兵值标记不限购，页面翻译为"无限额"
- **收益率**：红涨绿跌（暗色主题用降饱和色值）
- **最近变更列表**：包含美国基金与世界页基金的变更；世界页条目带市场小标签（如"中国香港"），美国基金不标

## 五、世界页数据的"新旧合并"

世界页有一份手工整理的**静态档案**（跟踪标的、申购手续费这类不常变的），每日**扫描数据**叠加其上：

| 字段 | 数据来源 |
|---|---|
| 申购状态、代销限额、直销限额、历史节点 | 每日扫描（有值必覆盖） |
| 跟踪误差、收益率、成立日、规模、管理/托管费率 | 每日扫描（有值覆盖），缺失保留档案值 |
| 跟踪标的 | 天天基金详情页每日扫描，有值覆盖，缺失回退静态档案 |
| 申购手续费 | 静态档案（与管理/托管费率不是同一字段） |
| 类型筛选 | 静态档案；列表申购状态使用每日扫描值 |

**整页兜底**：扫描数据文件整体缺失（如未部署）时，页面自动完全回退静态档案，不会白屏。

## 六、AI 日报解析任务（独立兜底通道）

当前代码不含模型 API 或已确认的 AI 定时执行器，不能把正则公众号解析描述成 AI。**AI 执行方式待确认后接入**；不应宣称 9:30 / 12:30 / 18:30 的任务已经生效。

已实现的统一导入入口是 `qdii-watcher/update_direct_from_ai.py`。外部 AI 应先检查网站是否失败、数据日期是否滞后，或目标基金的直销额度是否缺失；有需要时通过搜狗查找指定公众号最新文章，核对发布账号和日期、阅读正文，仅提取明确的直销额度，不猜测缺失值。

输入格式（额度为元；明确暂停为 0；未知基金直接省略）：

```json
{"as_of":"2026-09-19","source_url":"https://mp.weixin.qq.com/s/原文地址","funds":{"019454":1000,"012348":0}}
```

导入脚本要求有效的非未来数据日期、公众号原文链接、六位代码和有限非负数字。有效结果先保存到 `fund.db` 的独立 `direct_limits` 表，再刷新美国页、世界页和主动母池中已有的数据文件。缺失页面文件不凭空创建，等待扫描生成；主表和世界页共用同一额度记录。

```sh
python3 qdii-watcher/update_direct_from_ai.py --input /path/to/ai_direct_limits.json
```

默认输出到项目 `public/qdii/`。扫描器和导入器都支持 `--db`、`--out`、`--world-page-out`、`--world-out`；部署时两者必须使用同一个数据库路径和相同输出路径。两者通过同一个发布锁串行写入，AI 新数据不会被下次扫描的旧数据覆盖。

直销的 `direct_as_of`、`direct_source`、`direct_source_url` 随每只基金导出，保留原数据日期；抓取时间不等于数据日期。

## 七、容错规则

| 意外情况 | 处理方式 |
|---|---|
| 天天基金接口挂了 | 重试 3 次后放弃本轮，数据保持原样 |
| 某只基金详情页抓不到 | 该基金收益等字段空着，不影响其他基金 |
| 安鑫乐网站数据滞后或失败 | 保留库中较新的有效值；外部 AI 任务接入后补充公众号数据 |
| 公众号解析失败或 AI 输出非法 | 不写入无效结果，保留最近有效直销值；不清除通知比较基线 |
| 接口返回异常数字（文本/空值/NaN/Infinity） | 未知值保留 null；“万/万元/亿/亿元”按单位解析，禁止导出非有限数字 |
| 限额缺失 | 页面显示"—"，不与 0 混淆 |

## 八、已知边界与待拍板事项

1. **直销额度变化已参与邮件检测，但尚未进入扫描历史/“最近变更”列表**。邮件分别比较代销和直销额度；仅状态变化、新增基金或缺失值不会触发邮件。世界页数据也进入通知，按订阅地区过滤。
2. **"手续费"列是申购费折扣价**（静态档案值）；扫描抓的费率页口径不同（管理/托管/销售服务费），未纳入每日更新，避免张冠李戴。
3. **本轮修复仅在本地 dev，未部署**。2026-09-19 核实远端 main 为 644d580；线上公开扫描数据没有直销字段，不能以 main 提交日期推断独立扫描器的版本。
4. 部署配置已保护三个运行时扫描 JSON，避免前端发布覆盖服务器数据；首次上线需先生成世界页数据，再启用相关通知。AI 执行任务尚待确认配置。
